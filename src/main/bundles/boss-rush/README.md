# Boss Rush — Bundled Fallback

This directory ships the **Boss Rush** Bundle Instance inside the launcher EXE so
the app has at least one curated Bundle to offer on first start, even when the
machine is offline.

## Layout

```
bundles/boss-rush/
  manifest.json   Track-5 schema BundleManifest. The launcher reads this on
                  install and stores a copy at the installed instance root.
  README.md       This file.
  files/
    README.md     Placeholder explanation. In real builds the actual Mods/ +
                  UserData/ tree is dropped in here by the bundle author / CI
                  pipeline and the file list is regenerated by the
                  sync-bundled-bundles.mjs script (see below).
```

## How it is wired

1. **Authoring** — drop the curated Mods + UserData tree under
   `bundles/boss-rush/files/` (e.g. `files/Mods/BAPBAPBalanceMod.dll`,
   `files/UserData/BalanceMod/Library/AllOptions.index.json`, ...).
2. **Hashing** — `apps/bapbap-launcher/scripts/sync-bundled-bundles.mjs` walks
   `files/`, computes per-file SHA-256 + sizeBytes, and rewrites the `files[]`
   array in this folder's `manifest.json` while preserving every other
   top-level field (id, name, channel, version, buildNumber, publishedAtUtc,
   compatibility, sourceUrl, changelog, extra).
3. **Build pipeline** — `npm run build` (a.k.a. `npm run build:v2`) invokes
   `sync-bundled-bundles` after `sync-bundled-workspace` and before
   `electron-vite build`. The whole `default-workspace/` tree (including
   `bundles/`) is then copied to `dist/main/rebalance-vendor/` by
   `scripts/sync-rebalance-vendor.mjs`, which is what ends up inside the
   packaged Electron app. `sync-bundled-workspace.mjs` deliberately preserves
   the `bundles/` subdir during its rm-and-recopy cycle so this source-tree
   payload is not regenerated from the BalanceMod source root.
4. **Runtime** — `BundleService` (see `docs/bundle-instance/BUNDLE_INSTANCE_MASTER_SPEC.md`
   §5.1, §7) reads this manifest as the offline-first fallback when the user
   installs the bundle for the first time. After install, the auto-update
   service (Track 2) takes over and may replace these files with whatever the
   remote `sourceUrl.manifest` advertises.

## Why a placeholder ships in source control

`files/` is intentionally **empty (only this README)** in source control:

- the launcher must compile and `npm run build:v2` must succeed even when no
  curated Mods are checked into the repo (e.g. on a CI runner without LFS);
- the manifest tracks `extra.isPlaceholder: true` so the launcher can show a
  "this Bundle is a stub — please update before launch" warning if a build
  ever ships without the real payload;
- real release builds populate `files/` outside the source tree (or via an
  ignored side-channel) and re-run `sync-bundled-bundles.mjs` to refresh the
  manifest's `files[]` array prior to packaging.

## Editing the manifest

Edit only the *non-`files[]`* top-level fields here. The `files[]` array is
generated; manual edits will be overwritten by the next sync run. The bundle
`id` (`"boss-rush"`) MUST match the directory name and MUST stay stable across
releases — it is the launcher's primary key for update detection.
